# NeuroPlay MVP

## Overview : A web-based cognitive rehabilitation prototype with:
- Memory pattern game for patients
- Reaction sprint game for psychomotor speed
- Attention grid game for sustained attention
- C++ game logic and metrics processing compiled to WebAssembly
- PostgreSQL storage via Node.js API
- Doctor dashboard with Chart.js trends


## Features
* **Memory Pattern Game**: Built to target short-term memory and sequencing impairment. Focuses on memory retention consistency and sequencing accuracy.
* **Reaction Sprint Game**: Targets psychomotor delay, focusing on initiation speed and motor response latency.
* **Attention Grid Game**: Designed for sustained-attention deficits, tracking vigilance, misses, and visual scanning control.
* **Dynamic Difficulty Engine**: Automatically scales pattern lengths and challenge levels based on round accuracy (e.g., pattern length increases if round accuracy > 80%, decreases if < 50%).
* **Doctor Dashboard**: Provides real-time Chart.js trends and performance metrics for medical professionals.
* **Clinical Notes**: Stores diagnostic signals and improvement notes that the dashboard surfaces for follow-up therapy planning.


## Tech Stack & Tools
* **Core Logic Engine**: C++
* **WebAssembly (WASM)**: Emscripten Compiler
* **Frontend**: Vanilla JavaScript, HTML5, CSS3, Chart.js
* **Backend**: Node.js API
* **Database**: PostgreSQL


## Technical Workflow
1. **WebAssembly Bridge**: The core puzzle mechanics, performance metrics, and sequence generation are written in C++ for optimal performance. Emscripten compiles this C++ engine into a WebAssembly module (`engine.wasm`) and a JavaScript wrapper (`engine.js`).
2. **Frontend Interactivity**: The web client interacts directly with the compiled C++ functions via the JavaScript bridge (e.g., calling `Module._startPuzzle()`, `Module._recordClick()`).
3. **Data Persistence**: At the end of a session, game metrics (reaction time, accuracy, mistakes, hesitation time) are sent to the Node.js backend API.
4. **Database Storage**: The Node backend securely stores the session data, difficulty level, and clinical improvement notes into a PostgreSQL database.
5. **Dashboard Rendering**: The doctor dashboard fetches historical data from the API and visualizes patient trends over time using Chart.js.

## 1) Build C++ to WebAssembly

Open PowerShell in `neuroplay-mvp` and run:

```powershell
# Activate Emscripten for this terminal session
..\emsdk\emsdk_env.ps1

# Compile C++ engine
emcc .\cpp\engine.cpp -O2 -s WASM=1 -s ENVIRONMENT=web -s MODULARIZE=0 -s EXPORTED_RUNTIME_METHODS=[] -s EXPORTED_FUNCTIONS=['_startPuzzle','_recordClick','_setDifficulty','_getDifficulty','_getAccuracy','_getRoundAccuracy','_getAverageReactionTime','_getMistakes','_getSequenceLength','_getSequenceTile','_resetAll'] -o .\wasm\engine.js
```

This generates:
- `wasm/engine.js`
- `wasm/engine.wasm`

## 2) Setup PostgreSQL Backend

1. Create PostgreSQL database `neuroplay`.
2. Run schema setup:

```sql
-- from backend/schema.sql
CREATE TABLE IF NOT EXISTS game_sessions (
  id SERIAL PRIMARY KEY,
  user_id TEXT NOT NULL,
  game_name TEXT NOT NULL,
  reaction_time NUMERIC(10,2) NOT NULL,
  accuracy NUMERIC(5,2) NOT NULL,
  mistakes INTEGER NOT NULL,
  hesitation_time NUMERIC(10,2) NOT NULL,
  level INTEGER NOT NULL,
  diagnosis TEXT,
  improvement_note TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

3. Start backend API:

```powershell
cd .\backend
copy .env.example .env
# edit .env with your PostgreSQL credentials
npm install
npm run dev
```

API URL used by frontend: `http://localhost:4000/api`

Session row shape:
- `userId` (string)
- `gameName` (string)
- `reactionTime` (number)
- `accuracy` (number)
- `mistakes` (number)
- `hesitationTime` (number)
- `level` (number)
- `diagnosis` (string)
- `improvementNote` (string)
- `timestamp` (server timestamp)

## 3) Run Locally

Use any static server from `neuroplay-mvp` directory in a separate terminal.

Option A (Node):
```powershell
npx serve .
```

Option B (Python):
```powershell
python -m http.server 8080
```

Then open:
- Main game hub: `http://localhost:8080/index.html`
- Doctor dashboard: `http://localhost:8080/dashboard/doctor.html`
- Reaction Sprint: `http://localhost:8080/games/reaction.html`
- Attention Grid: `http://localhost:8080/games/attention.html`

## 4) Difficulty Logic

At the end of each round:
- If round accuracy > 80%, pattern length increases by 1.
- If round accuracy < 50%, pattern length decreases by 1.
- Pattern length stays within [2, 12].

## 5) WebAssembly Bridge

JavaScript calls exported C++ functions through:
- `Module._startPuzzle()`
- `Module._recordClick(tile, reactionTime)`

Additional metrics/helper functions are also exported and used by UI.

## 6) Notes

- Browser autoplay/timing differences can slightly affect measured reaction times.
- `firebase.js` remains only as a compatibility wrapper and no longer uses Firebase.
- For production, add authentication, HTTPS, and role-based access for doctor/patient views.

## 7) Clinical Intent By Game

- Memory Pattern (WASM): Built for short-term memory and sequencing impairment. Output diagnosis signal focuses on memory retention consistency and sequencing accuracy.
- Reaction Sprint: Built for psychomotor delay. Output diagnosis signal focuses on initiation speed and motor response latency.
- Attention Grid: Built for sustained-attention deficits. Output diagnosis signal focuses on vigilance, misses, and visual scanning control.

Each game stores an improvement note that the doctor dashboard surfaces for follow-up therapy planning.
